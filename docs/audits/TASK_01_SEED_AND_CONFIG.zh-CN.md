# T01：种子与配置传递

英文原文：[TASK_01_SEED_AND_CONFIG.md](TASK_01_SEED_AND_CONFIG.md)

- 状态：计划覆盖全部 21 个适配器
- 上级方案：[跨 Baseline 流水线真实功能审计](PIPELINE_REAL_FUNCTION_AUDIT.zh-CN.md)
- 风险类型：无声的科学错误

## 目标

证明仓库配置按照预期值到达权威运行时。重点发现上游默认值被写死、字段丢失、优先级错误、训练/生成种子混淆，以及验证后又被修改的配置。

## 每个适配器的 V0/V1 检查

- 从 CLI/配置模型开始，沿 `RunSpec`、适配器调用、子进程参数/环境变量一直追踪到权威 API 或源码入口。
- 记录用户值、数据集 profile 值、适配器默认值和上游默认值的精确优先级。未知或互相冲突的字段必须在训练前报错。
- 验证训练种子、生成种子、评测种子和 `PYTHONHASHSEED` 没有被无声混用。
- 验证非负种子检查、确定性模式处理，以及无法满足复现请求时的明确提示。
- 验证权威运行时实际打开的就是用户请求的配置路径，并在证据中绑定其哈希。
- 验证适配器不会原地修改纳入版本控制的上游配置或源码。
- 验证运行中保存的解析后配置不包含凭证，并足以重建本次调用。

受控测试替身可以观察参数和环境变量，但这种结果只能算 V1，必须标记为 `contract-simulated`。

## V2 最小真实探针

使用小型有效数据，以及仍会调用权威训练和生成算法的最快模型专属配置。

1. 第一次真实执行使用一个预先声明的、非默认且非零的种子。
2. 确认保存的解析后配置与权威运行时实际收到的值一致。
3. 如果训练和生成可分离，则复用检查点执行第二个生成种子并保留两份输出；否则执行该模型支持的最小第二次种子运行。
4. 随机生成通常必须产生不同文件哈希；若预期相同，模型协议必须说明原因。
5. 只有上游方法声明被测平台支持位级复现时，才要求位级一致。此时重复相同种子，并比较协议指定的产物。

## 失败条件

- 用户值被接受但没有生效。
- 种子角色被调换、重置或强制成隐藏常量。
- 第二个种子覆盖或无声复用第一个样本。
- 无法根据保存的元数据还原实际运行配置。
- 模拟检查通过，但权威真实入口收到不同的值。

## 退出条件

每个未被阻塞的适配器都具有参数/配置追踪和 V2 观察。每个已确认缺陷都写入 [PIPELINE_FINDINGS.zh-CN.md](PIPELINE_FINDINGS.zh-CN.md)，完成根因修复，并在最窄的公共边界添加回归测试。
