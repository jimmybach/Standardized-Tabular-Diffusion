# T02：数据与输出契约

英文原文：[TASK_02_DATA_AND_OUTPUT_CONTRACT.md](TASK_02_DATA_AND_OUTPUT_CONTRACT.md)

- 状态：全部 21 个注册身份已完成 V0/V1；20 个未阻塞身份均保留通过的解码表观察，TabEBM 保留明确的外部访问阻塞
- 上级方案：[跨 Baseline 流水线真实功能审计](PIPELINE_REAL_FUNCTION_AUDIT.zh-CN.md)
- 风险类型：数据泄漏、结构损坏或无声修复输出

## 目标

证明每个适配器只使用声明的真实数据角色，并生成数量正确、已经解码且科学含义未被改变的表。检查范围包括列顺序、逻辑类型、缺失值、行数、目标列、类别、整数以及仅在训练集拟合的预处理。

## 每个适配器的 V0/V1 检查

- 模型执行前，把训练、验证、测试和元数据路径解析到精确文件及其哈希。
- 验证训练不会通过预处理、词表构建、归一化、填补或模型选择读取留出测试集的值。
- 原始数据存在允许的缺失值时，必须使用中央预处理器。均值和众数只能在真实训练集拟合；目标缺失和生成结果填补必须报错。
- 验证数据集 profile 的逻辑类型如何转换为上游表示，又如何恢复成原始解码结构。
- 保留声明的列名和顺序。重复列名、缺列、多列和不支持的类型必须在评测前报错。
- 分别检查 Boolean、类别、整数、浮点和目标列。解码后整数列必须为整数；类别输出必须符合对未知类别的既定策略。
- 精确检查请求生成行数，包括 batch 余数和小于一个 batch 的请求。
- 输出校验只能报告问题，不能无声截断、取整、删行、重排、填补或修复；只有经过审阅的适配器解码契约明确要求的变换才例外。
- 适配器声明支持二分类、多分类和回归时，要分别覆盖这些任务类型。

## V2 最小真实探针

保留输入/profile 校验和，通过权威算法生成一份小型解码表。执行中央结构门并记录：

- 精确行列数；
- 有序列名；
- 解码后的逻辑类型；
- 缺失、非有限、整数列小数和未知类别数量；
- 目标列是否存在及其角色；
- 进入评测前的输出文件哈希。

结构门必须检查模型原样生成的表。任何单独的诊断性修复都必须生成新的明确标记产物，且该产物不能进入正式评测。

## 失败条件

- 留出测试信息影响训练或仅训练集拟合的预处理。
- 生成值违反声明结构，但运行仍被报告为成功。
- 请求行数与输出行数不同。
- 目标列或特征列被无声删除、改名、重排或强制转换。
- 不合规生成表在进入中央评测前被原地修复。

## 退出条件

每种受支持任务类型都有契约覆盖，每个未阻塞适配器都有 V2 解码表观察，并且所有无声变换都已删除，或被记录为具有等价证据的权威解码操作。

## 完成记录

共享输入身份、仅训练集拟合的预处理、结构、行数和不可变输出门禁均有回归测试。18 个最小真实 Windows 探针和 2 个代表性真实记录生成的表格都通过了声明的结构契约及中央 P3 最终化，且没有修复合成数据。TabEBM 在完整生成前仍受外部条件阻塞。该记录只证明留存身份的功能，不会让任何数据集、模型或结果自动进入正式榜单。
