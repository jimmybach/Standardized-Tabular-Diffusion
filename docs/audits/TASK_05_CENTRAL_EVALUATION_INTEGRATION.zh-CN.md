# T05：中央评测集成

英文原文：[TASK_05_CENTRAL_EVALUATION_INTEGRATION.md](TASK_05_CENTRAL_EVALUATION_INTEGRATION.md)

- 状态：18 个未阻塞最小真实 baseline 已全部完成；GReaT、REaLTabFormer 与 TabSyn 现也保留了使用独立依赖锁最终化的 `p3-validity` bundle
- 上级方案：[跨 Baseline 流水线真实功能审计](PIPELINE_REAL_FUNCTION_AUDIT.zh-CN.md)
- 风险类型：模型专属评测漂移，或错误地最终化结果

## 目标

证明每个公开适配器路径都会把未被修改的解码样本交给同一中央评测子系统。适配器可以负责训练、生成和权威解码，但不能私自计算指标公式、绕过结构门，或把旧版 summary 当作当前结果发布。

## 每个适配器的 V0/V1 检查

- 从 `run-action evaluate`、顶层 `run` 和 `benchmark run` 开始，追踪所选样本产物是否进入公开中央评测服务。
- 验证实际选择的生成种子、样本路径、样本哈希、模型身份、数据集 profile 身份和解析后的协议均被保留。
- 验证适配器自己的 `evaluate` 只负责路由，不会选择模型专属公式，也不会无声退回 `standardized_summary.json`。
- 验证协议选择明确：P2、P3、P4、P5 需要不同的数据角色和依赖，不能根据目录里恰好有什么文件进行猜测。
- 验证不合规输出在指标计算前就被对应协议的结构门拒绝。
- 验证逐作用域 Atomic Result 保留完整分母、状态、来源值、派生值和失败记录。
- 验证 bundle finalization 最后发生；文件或身份存在任何不一致时都必须拒绝最终化。
- 验证外部合成表也能直接评测，无需导入任何模型适配器。
- 验证模型专属训练依赖与中央评测依赖分别冻结；最终化必须核验中央依赖锁，不能依赖模型环境中偶然存在的包。

## V2 最小真实探针

使用适配器 V2 真实运行产生的同一份样本，调用成本最低且兼容的中央结构/评测路径。至少需要：

1. 评测前绑定样本文件哈希。
2. 确认请求记录实际生成种子和模型运行身份。
3. 对结构有效样本最终化并校验一个 bundle。
4. 在副本中制造一个已知结构错误，确认它会封闭失败且不改变原始样本。
5. 确认没有导入或写出旧评测器或适配器私有指标路径。

V3 候选使用经过审阅的 P2/P3 路径，以及单独要求的 P4/P5 协议。V2 通过不代表每个指标都适用或已获准入。

## 失败条件

- 评测读取了另一个种子或旧样本。
- 适配器绕过中央注册表自行计算或选择分数。
- 结构失败被修复操作掩盖，或通过丢弃无效作用域隐藏。
- 不完整或校验和不一致的 bundle 被标记为 finalized。
- 同一解码表仅因来自不同适配器而使用不同公式。

## 退出条件

所有适配器入口都汇入同一个按协议解析的服务；有效 V2 输出能最终化为通过校验的中央 bundle；不合规副本会封闭失败；回归测试禁止退回旧版或私有评测器。
