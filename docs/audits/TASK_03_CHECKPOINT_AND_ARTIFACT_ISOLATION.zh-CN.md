# T03：检查点与产物隔离

英文原文：[TASK_03_CHECKPOINT_AND_ARTIFACT_ISOLATION.md](TASK_03_CHECKPOINT_AND_ARTIFACT_ISOLATION.md)

- 状态：共享流水线边界已完成；20 个未阻塞身份均保留隔离且不可变的 Windows V2 或更强产物，TabEBM 保留明确的外部访问阻塞
- 上级方案：[跨 Baseline 流水线真实功能审计](PIPELINE_REAL_FUNCTION_AUDIT.zh-CN.md)
- 风险类型：误用旧结果、运行间污染或破坏性覆盖

## 目标

证明每次运行独占自己的检查点、日志、解码样本、元数据和评测 bundle。适配器不能误读上游示例检查点、前一个种子的输出或写了一半的产物，然后把它报告成一次新的成功。

## 每个适配器的 V0/V1 检查

- 追踪上游代码使用的全部读写路径，包括写死的工作目录、临时文件、缓存、检查点、图片和默认结果目录。
- 所有可变输出都必须绑定到请求的 `output_dir` 或隔离运行目录。纳入版本控制的上游源码树保持只读。
- 运行目录和种子子目录必须不易冲突。不同生成种子不能共用同一个最终样本路径。
- 未明确覆盖语义时，非空目标目录必须报错。不能仅因旧文件存在就推断本次成功。
- 原子写入完成后记录检查点和样本哈希。读取前验证大小、格式及必需的伴随文件。
- 验证 resume/cache key 包含所有会影响产物的科学身份和运行身份。
- 验证失败或中断写入不能替换上一份已知完整产物。
- 大型产物继续由 Git 忽略；只有经过批准时才保留精简证据 manifest。

## V2 最小真实探针

1. 在全新的隔离目录中真实训练一次，记录完整文件清单。
2. 使用第一个声明种子生成；支持时再使用第二个种子，验证路径和哈希相互独立。
3. 在受控目标中放置故意过期或不完整的哨兵文件，证明适配器会拒绝它或建立新的隔离尝试。
4. 只有通过声明的 resume/cache 机制才能重复完全相同的请求，并证明复用前执行了身份校验。
5. 确认版本控制中的上游文件没有变化。

## 失败条件

- 新运行因为发现无关的旧检查点或旧样本而成功。
- 两个种子互相覆盖，或中央评测读到了错误种子。
- 不完整输出被当作完成。
- 缓存复用忽略协议要求的配置、数据、源码、种子、平台或依赖身份。
- 权威源码树被当作可写运行目录。

## 退出条件

每个适配器都有完整路径图和隔离测试。所有真实探针都生成可复核 manifest，旧产物哨兵能够安全失败，并且 retry/resume 行为具有回归测试。

## 完成记录

运行身份、数据集身份、逐种子输出所有权、原子最终化、缓存校验和重试祖先关系均在共享边界强制执行并由回归测试覆盖。每个留存的 Windows 真实功能通过记录都证明训练产物保持不变，并为两个声明的生成种子记录独立哈希；TabDDPM 和 TabDiff 的代表性记录满足更强的 V3 边界。任何被跟踪的上游源码都不会被当作可变运行目录。这里不宣称所有上游实现都原生支持断点恢复。
