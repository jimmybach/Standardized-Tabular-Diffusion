## 1. 结果

第一阶段的 10 个发现均已完成根因代码修复和回归覆盖。它们在台账中的状态为 `fixed`，而不是 `verified`：本阶段执行了静态检查和受控 V1 模拟，包括对官方进程输出的模拟，但没有为每个受影响模型重新执行权威算法的 V2 训练与采样探针。

本阶段没有修改任何权威模型方程、损失函数、优化步骤或采样方程。TabDDPM、TabDiff 和 TabSyn 的改动均位于适配器/运行时边界，包括运行配置、数据绑定、检查点位置和解码输出所有权。受校验和锁定的上游源码树保持不变。

## 3. 安全性与兼容性决策

- 数据集符号链接、非常规输入、不安全检查点，以及符号链接形式的输出/运行目录都会封闭失败。
- TabDDPM 的运行时 TOML 序列化不新增依赖，并使用 `tomllib` 重新解析；若语义往返结果不同，执行立即停止。
- TabDDPM 采样必须复用已记录的运行所有检查点清单和训练科学配置；采样边界只允许采样种子、请求行数、设备及路径绑定发生变化。
- TabDiff 和 TabSyn 仍从固定上游仓库导入官方实现，只重定向可变运行路径。
- 未嵌入公共数据身份的底层 `adapter.train(RunSpec(...))` 测试夹具保留诊断兼容路径；公共 `train_from_config`、`sample_from_config`、`run-action` 和 `run` 始终嵌入并强制执行内容身份。

## 4. 验证边界与下一步

修复后，完整的轻依赖仓库测试套件通过。这证明了当前仓库快照的 V0/V1 契约行为；它不证明新的原生 Windows 真实模型功能、输出质量、原生等价性、榜单准入、Official Results 准入或发布支持。

下一阶段是 V2：按照已批准的由快到慢批次，为每个未受外部阻塞的适配器执行最小真实权威训练/采样探针。只有对应 V2 探针通过后，发现状态才会从 `fixed` 更新为 `verified`。
