# T06：失败与恢复

英文原文：[TASK_06_FAILURE_AND_RECOVERY.md](TASK_06_FAILURE_AND_RECOVERY.md)

- 状态：共享流水线边界已完成；真实失败及其关联的干净重跑均已保留，唯一外部阻塞保持明确
- 上级方案：[跨 Baseline 流水线真实功能审计](PIPELINE_REAL_FUNCTION_AUDIT.zh-CN.md)
- 风险类型：假成功、无法恢复的半成品状态，或泄露敏感上下文

## 目标

证明预期失败会被明确分类，已完成工作能够安全保留，并且可以确定性重试，而不会把失败的科学计算伪装成成功。

## 每个适配器的 V0/V1 检查

- 列出启动前、训练中、检查点保存/加载、生成/解码和中央评测阶段的失败。
- 覆盖无效配置、负种子、缺依赖/源码、缺数据集、结构不匹配、不可能的行数、不支持的任务类型、请求设备不可用、超时和子进程失败。
- 必须返回非零进程码、结构化阶段状态、可操作的公开错误和已经脱敏的诊断日志。
- 保留尝试链。重试应建立关联失败的新 attempt，而不是改写先前记录。
- 验证清理不会删除其他运行的成功产物，且半成品文件不能被选为完整结果。
- 验证 cache/resume 只接受校验和完整且身份精确匹配的输出。缓存损坏时必须重新执行。
- 从命令、日志、错误和保留证据中删除 token、凭证、敏感环境值以及非预期的原始数据行。
- 区分“只修复环境后重试”和“改变科学配置或种子后重跑”。

## V2 有边界的失败探针

使用适配器最小真实设置，只测试安全边界：

1. 在昂贵计算前请求不可用或无效设备，确认会封闭失败。
2. 中断或限制一次可丢弃运行，验证完整进程树终止，且不会最终化任何产物。
3. 破坏检查点或缓存 manifest 的副本，确认会拒绝且不触碰原件。
4. 只修复声明的环境故障，作为关联 attempt 重试；只有身份校验通过时，才能复用互相独立的已完成阶段。

不能注入可能损害用户主要检查点或未提交数据的故障。所有破坏性探针都只能在隔离的可丢弃目录执行。

## 失败条件

- 子进程失败后整体仍返回成功，或留下 finalized bundle。
- 重试隐藏、替换失败 attempt，或与它失去关联。
- 损坏或身份不匹配的产物被复用。
- 日志或证据含有凭证或非预期的原始敏感值。
- 清理操作越过隔离运行边界。

## 退出条件

每类公共失败都有确定性测试；适配器专属异常全部映射到结构化状态；安全重试已经演示；除非明确列为发布阻塞，否则不得遗留 S0/S1 失败处理问题。

## 完成记录

编排测试套件验证了结构化失败状态、子进程失败的非零退出、超时处理、仅复用校验和完整的缓存、attempt 祖先关系以及关联重试成功。第三阶段没有删除 TabularARGN、ARF 和 NRGBoost 的首次失败，而是保留它们，并记录精确的环境修复及干净重跑。TabuLa 上游无界生成重试循环被限制在 Windows 子进程超时边界内；TabEBM 的受限依赖被明确报告为外部阻塞。目前没有未解决的 S0/S1 失败处理问题。
