# 项目总路线与整体进度

状态日期：2026-08-21

范围：整个项目阶段状态的唯一权威来源

当前工作焦点：**阶段 7——V3 代表性科学验证（`⬜ 待完成`；执行前需要讨论）**

## 1. 文档目的

本文档是 Standardized Tabular Diffusion 整个项目的权威进度索引，专门回答三个问题：

1. 整个项目现在处于哪个阶段？
2. 一个阶段需要哪些证据才能改变状态？
3. P1-P8、V0-V3 等子系统编号如何映射到整个项目？

子系统路线图仍然是各自技术合同的权威文档，但不得被解读为整个项目的时间表。特别是：

- **P0-P8** 表示评测与发布工程实施包。
- **V0-V3** 表示 baseline 运行验证等级。
- **本文档的阶段 1-10** 才表示整个项目。

P8 完成不代表项目总阶段 7-10 也已完成。同样，本地安装验收属于项目总阶段 9，它不是一个新的 P9 评测协议。

## 2. 状态词汇

| 状态 | 含义 |
|---|---|
| ✅ 完成 | 声明范围和退出证据均已完成。未来发布时的专项复查不会让基础阶段重新变为未完成。 |
| ✅ 在声明范围内完成 | 仓库在法律和技术上能够执行的全部目标均已通过；已命名的外部例外被保留，并从通过率分母中排除。 |
| ✅ 基本完成 | 声明的公开可访问范围内已全部完成，但仍有一个已命名的外部依赖阻塞。 |
| 🟡 待集成 | 实现和本地验收已通过，但精确改动尚未提交、审阅、合并，也未由托管 CI 重新验证。 |
| ⬜ 待完成 | 阶段章程或必需执行尚未完成。 |
| ⏸ 延期/可选 | 在项目需要该发布等级之前，有意推迟该阶段。 |
| 🚫 外部阻塞 | 继续推进需要仓库维护者无法在本地提供的访问权、权利或基础设施。 |

总阶段是门禁，不是强制的日历顺序。可以先完成阶段 9 的工程工作，让后续阶段 7-8 的科学实验建立在可靠软件包上。进度表只记录实际通过的内容，不为了数字顺序而改写事实。

## 4. 各阶段定义与退出证据

### 阶段 1：仓库基础治理

退出条件：仓库自有代码具有明确许可证和署名边界；贡献、安全、数据治理、平台和第三方政策存在；不支持的声明会失败关闭。

主要记录：[LICENSE](../LICENSE)、[NOTICE](../NOTICE)、[第三方声明](../THIRD_PARTY_NOTICES.md)、[贡献指南](../CONTRIBUTING.md)、[安全政策](../SECURITY.md) 和[质量标准](QUALITY_STANDARD.md)。

发布时的密钥/历史复查属于阶段 10，不会让这个基础阶段重新变为未完成。

### 阶段 2：Baseline 接入

退出条件：每个选定 baseline 都已注册，暴露统一的外部生命周期，声明支持的任务/数据/设备边界，并把评测路由到中央引擎。

当前结果：21 个已注册适配器。运行状态由[运行状态文档](runtime_status.md)维护。

### 阶段 3：上游来源与等价验证

退出条件：每个可访问适配器都识别精确权威来源、revision/包、再分发状态、修改分类、等价协议和保留证据。外部访问限制必须被记录，不得用未验证实现替代。

当前结果：20 个 `native-parity-validated`；TabEBM 是已声明外部例外。见[上游来源审计](UPSTREAM_SOURCE_AUDIT.md)。

### 阶段 4：P1-P8 评测与发布工程基础设施

退出条件：评测合同与注册表、Atomic Results、Result Bundles、P2-P5 指标、P6 编排、P7 聚合/发布以及 P8 迁移/打包界面均通过各自工程门。

当前结果：P1-P8 工程门已通过。这不会将任何数据集、模型、指标、运行或结果准入 Official Results。见 [P1-P8 实施路线](evaluation/IMPLEMENTATION_ROADMAP.zh-CN.md)。

### 阶段 5：原生 Windows 真实功能验证

退出条件：每个非阻塞适配器都在原生 Windows/Python 3.11 上执行有界的真实权威 fit/generate 流程，保持产物/seed/输出合同，并达到独立中央 bundle 校验。先前已完成的更强运行可满足同一功能门，无需重复。

当前结果：所有公开可访问适配器均满足声明的 Windows 功能范围；TabEBM 仍为外部阻塞。见[跨 baseline 真实功能审计](audits/PIPELINE_REAL_FUNCTION_AUDIT.zh-CN.md)。

### 阶段 6：V2 总审计收尾

退出条件：共性逻辑问题已通过测试关闭，运行证据已建立索引，没有可访问 V2 目标仍为 pending，未解外部阻塞明确，并且全仓库回归检查通过。

当前结果：逻辑审计、修复阶段、V2 执行和全仓库回归均已完成。这是运行证据，不是生成器质量证据。

### 阶段 7：V3 代表性科学验证

退出条件：执行前必须审批一个有界代表性矩阵，其中包含：

- 模型列表及其纳入理由；
- 已准入的数据视图和已审阅 Dataset Profile；
- native 或已批准的 `standardized-tuning` 配置；
- 除非协议要求更多，精确声明三个生成 seed；
- 计算/资源限制和失败政策；
- P2-P5 指标适用性与科学判定规则；
- 防止将探索结果重新标注为验证性证据的规则。

当前结果：已有独立三种子协议确认和科学 pilot，但尚无已批准的整体 V3 计划，因此本阶段仍待讨论。

### 阶段 8：正式 benchmark 实验

退出条件：执行完整已批准模型×数据集×种子矩阵；校验每个 Result Bundle；记录 missing/failed 分母；创建独立准入记录；在不混合不兼容 track 或环境的前提下发布不可变榜单快照。

当前结果：基础设施存在，但正式实验执行和带排名的 Official 快照尚未开始。见 [P7 聚合与榜单合同](evaluation/P7_AGGREGATION_AND_LEADERBOARD.zh-CN.md)。

### 阶段 9：内部可用版本收尾

退出条件：针对精确已集成候选，在干净 Python 3.11 环境中分别安装 wheel 和源码包；按文档执行从数据获取到 Result Bundle 的流程；验证代表性 CPU/GPU 流程；测试空格和非 ASCII 路径；审计 CLI/错误/输出行为；并证明发行归档不含数据集、运行产物、凭证、保留机器证据或开发机本地路径。

当前结果：所有本地验收动作已通过，包括记录中的 646 项测试验收环境、全仓库 Ruff 与 Mypy、独立 wheel/源码包安装、Adult 下载与预处理、CPU SMOTE 和 RTX 5080 CTGAN。后续 Python 3.11/3.13 集成审阅与新发行包检查也已通过。[PR #34](https://github.com/jimmybach/Standardized-Tabular-Diffusion/pull/34) 已合并为 [`1d500e1`](https://github.com/jimmybach/Standardized-Tabular-Diffusion/commit/1d500e18c00dcb866b1d3c1e7e81931a025baf98)；该精确 `main` commit 的 13 个工作流全部通过，包括 [Core CI](https://github.com/jimmybach/Standardized-Tabular-Diffusion/actions/runs/32511293539) 和 [Windows/Linux P8 发布门](https://github.com/jimmybach/Standardized-Tabular-Diffusion/actions/runs/32511293507)。见[干净安装验收报告](audits/CLEAN_INSTALL_USER_ACCEPTANCE.zh-CN.md)。

### 阶段 10：正式公开发布

退出条件（启动时）：选择并冻结版本；对精确 commit 重复发布候选安全、法务、历史、打包、Windows 和 Linux 门；发布校验和与 release notes；独立安装已发布产物；完成任何选定的 Organization 转移、网站、DOI 或论文材料。

当前结果：故意延期。见[发布检查清单](../RELEASE_CHECKLIST.md)。

## 7. 更新规则

1. 每次总阶段状态改变时，本文档必须与[英文主文档](PROJECT_ROADMAP.md)同步更新。
2. 子系统文档可以报告自身完成，但不得静默改变项目总阶段。
3. 每次转入“完成”都必须链接到保留证据或可审计的已合并实现状态。
4. 本地通过在精确改动已提交且必需托管门通过前，必须标记为本地。
5. 外部阻塞必须命名无法访问的依赖或权利，不得统计为仓库运行失败。
6. 科学协议完成、模型等价、benchmark 准入、发布支持和 Official Results 准入仍是相互独立的声明。
7. 每次进度表变更时，必须更新顶部的状态日期。
